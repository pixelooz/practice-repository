# System Design Interview Guide: What Is Actually Asked

Built from interview-frequency tallies and reported-question lists, in three tiers: ⭐ **Core** (asked constantly), 📘 **Common**, 🧗 **Rare**. It has three parts: design questions, the concepts those questions test, and low-level design.

> **Short version for a fresher:** learn the **11 Core questions** at a basic level, the **Core concepts** behind them, and the **Core LLD problems**. That is about 30 items, not 150. Everything else is optional until a specific company asks for it.

**Tier rule for questions:** score = average of (PracHub count ÷ 11) and (cross-check agreement ÷ 4). **Core** is 0.68 or higher, **Common** is 0.30-0.67, **Rare** is below 0.30. The cross-check counts how many of DesignGurus, SystemCity, MockExperts and IGotAnOffer include the question.

**Please keep these limits in mind:**

- A count measures how many lists agree a question matters, not how often interviewers ask it. PracHub says as much about its own tally.
- Several sources are prep vendors with something to sell, and Glassdoor skews to big US tech. System design questions are also harder to attribute than coding ones, because candidates rarely post dated reports and much of what circulates is recycled canon.
- I found **no frequency data specific to freshers or to Indian companies**, other than LLD lists with SDE-I tags. The fresher guidance below comes from level-expectation sources, not from counts.

## 2. What a fresher is actually expected to know

- **Foundations, not depth.** Per DesignGurus, junior candidates (Google L3-L4, Amazon SDE I, Meta E3-E4) aren't expected to produce production-ready designs. Interviewers want foundational reasoning: what a load balancer does, basic database choices, structured communication. Its advice for juniors is to deeply understand 8-10 core questions.
- **Breadth gets probed.** Hello Interview's founder says that at mid-level he takes no knowledge for granted: if you mention an API gateway, expect to be asked what it does and why it's needed. So know what each component you draw does.
- **Trade-offs are the usual failure.** Every source stresses stating alternatives and defending a choice (SQL vs NoSQL, push vs pull, consistency vs availability).
- **Whether you get a design round at all is company-dependent.** Many fresher loops use LLD or machine coding instead (Part 4).

### The eight patterns underneath

PracHub's tally observes that the 30 questions collapse into eight patterns. Learn the pattern from the Core question, and the rest follow:

| Pattern                                                     | Learn it from (Core / Common)                                                    | It also unlocks (Rare, mostly)       |
| ----------------------------------------------------------- | -------------------------------------------------------------------------------- | ------------------------------------ |
| Tiny-payload lookup at huge read ratios                     | URL shortener                                                                    | Key-value store, Unique ID generator |
| Feed fan-out                                                | News feed, Instagram                                                             | —                                    |
| Long-lived connections and ordering                         | Chat app, Google Docs                                                            | —                                    |
| Media and blob pipelines                                    | Video streaming, File sync                                                       | Object storage                       |
| Geospatial index and matching                               | Ride sharing, Google Maps, Proximity service, Food delivery                      | Tinder                               |
| Contended inventory and money                               | Ticketmaster, Payment system                                                     | Hotel booking, Stock exchange        |
| Streaming aggregation                                       | Typeahead / autocomplete, Metrics / monitoring system                            | Ad click aggregator, Leaderboard     |
| Coordination primitives (queues, limits, schedules, caches) | Rate limiter, Distributed cache, Web crawler, Notification system, Job scheduler | LLM serving, Message queue           |

The Core set covers seven of the eight patterns. The missing one is contended inventory and money (**Ticketmaster**, payments), which is why Ticketmaster is the first Common question to add.

## 4. Part B: The concepts those questions test

I counted how many of the 11 Core questions test each concept, using the "what it tests" descriptions in PracHub and DesignGurus. The mapping from description to concept is my reading, so treat the counts as approximate. **Core** means tested by 5 or more of the Core questions, **Common** 2-4, and **Question-specific** 1 (learn it inside the one question that needs it).

**Assumed in every answer** (not counted below, since every question needs them): back-of-envelope estimation, API design, load balancing and basic networking, database choice and indexing (SQL vs NoSQL, schema), requirements gathering, and stating trade-offs. DesignGurus lists skipping estimation and ignoring trade-offs among the most common reasons for rejection, and it expects juniors to understand basic database choices. Learn these first: [numbers to know](https://www.hellointerview.com/learn/system-design/core-concepts/numbers-to-know), [API design](https://www.hellointerview.com/learn/system-design/core-concepts/api-design), [networking essentials](https://www.hellointerview.com/learn/system-design/core-concepts/networking-essentials), [data modeling](https://www.hellointerview.com/learn/system-design/core-concepts/data-modeling), [indexing](https://www.hellointerview.com/learn/system-design/core-concepts/db-indexing), [delivery framework](https://www.hellointerview.com/learn/system-design/in-a-hurry/delivery). ## 5. Part C: Low-level design / machine coding

Many fresher loops, especially at Indian product companies, use an LLD or machine-coding round instead of, or alongside, high-level design. IGotAnOffer says to prepare for OOP, design patterns, SOLID, interfaces and class relationships. No source publishes frequency counts for LLD, so I tallied presence across the five lists above (two of them show only part of their contents, so these counts are lower bounds). **Core** is 3 or more lists, **Common** is 2, **Rare** is 1.

**First learn the toolkit:** OOP basics and SOLID ([awesome-low-level-design](https://github.com/ashishps1/awesome-low-level-design), [Hello Interview LLD](https://www.hellointerview.com/learn/low-level-design)), then the patterns that these problems keep using: [Strategy](https://refactoring.guru/design-patterns/strategy), [Observer](https://refactoring.guru/design-patterns/observer), [State](https://refactoring.guru/design-patterns/state), [Factory Method](https://refactoring.guru/design-patterns/factory-method). For concurrency in LLD, see [🎥 why count++ isn't atomic](https://arpitbhayani.me/videos/why-count-plus-plus-is-not-atomic-assembly-micro-operations), [🎥 mutexes](https://arpitbhayani.me/videos/understanding-pessimistic-locking-with-mutex), [🎥 thread-safe queue](https://arpitbhayani.me/videos/concurrent-thread-safe-queue-from-scratch).

## 6. Suggested order

1. **Process and vocabulary:** the delivery framework, estimation numbers, and the "assumed in every answer" items above.
2. **Core concepts** (Part B), reading the matching DDIA chapter where it's flagged 📗.
3. **Core questions** (Part A), one at a time: sketch your own design on paper first, then read the breakdown. Do Ticketmaster early to cover the contention pattern.
4. **Core LLD problems** (Part C), coding each in a timed hour.
5. **Common** items only after that. **Rare** items only if a specific company or role asks.

## 7. Relationship to the earlier study guide

The earlier `system-design-study-guide.md` is a broad reference menu that I ordered by my own judgment, not by data. This guide replaces it for prep. ## 8. About GenAI questions

Sources disagree on how common AI-system questions are. One guide claims they are about half of big-tech rounds, with no data shown. PracHub's tally has LLM serving in only 3 of 11 lists, and Aced (formerly Exponent) reports inference batching as Anthropic's most commonly reported prompt. The safest reading is that they are real but concentrated at AI companies, so they are Rare for a fresher unless you target those firms.
